# Outcome

完成 D6 data-align：在 D5 受控写入链上增加完全对齐，在明确范围内插入、更新和删除，并让删除影响、冲突及部分提交可检查、可解释。

# Scope

依据 docs/design/roadmap.md D6、overview.md F17/F19 与第 6 节、interaction-design.md 数据页；沿用 PRODUCT.md 技术栈和已归档 D4/D5 契约。

- 增加显式选择的完全对齐模式；默认仍为补齐。左右两方向每次只写一端。
- 对完整扫描覆盖的共享 AND 条件范围生成全部增改删计划；页面搜索、分类及分页不缩小执行范围。无条件时明确显示全表。
- 完全对齐针对可靠键和选定字段；不更新键或未选字段，不修改结构。
- 删除目标范围内、源扫描范围中不存在的键；范围外目标记录保留，范围外同键冲突阻止覆盖。
- 删除预览、独立删除确认、分批事务、冲突检测、停止、持久记录与重新比对。

# Non-goals

REPLACE、TRUNCATE、DROP TABLE、无键猜测匹配、自动关闭约束或触发器、自动跨表修复、任意 SQL/脚本、持续同步、全任务回滚、未知提交自动重试、业务库或生产库操作、D7 打包及新增平台发行承诺。

# Acceptance examples

- A1：左→右及右→左完全对齐均能插入源独有、更新同键选定差异字段、删除目标范围内独有记录；未选字段和键不更新。默认补齐及既有合并模式仍不删除。
- A2：仅完整有效扫描和可靠兼容键可生成计划；取消、失败、不完整、无键、非 InnoDB 或依赖不可见均拒绝。共享筛选范围外记录保留，范围外同键按目标真实键语义报冲突；空源范围可列出范围内全部删除，未确认不得执行。
- A3：预览显示实际目标、方向、模式、键、字段、共享条件或全表、读取时间、增改删数及分页 SQL/样例；删除明细单独可查。存在删除时须明确勾选认可删除数量与范围，再作执行摘要确认；未确认、旧计划、重复请求或迟到响应均不启动额外写入。
- A4：删除前在同批事务中按可靠键锁定目标，核对完整旧值及范围；目标已改、已删或移出范围、结构/权限漂移均停止并回滚本批，不覆盖并发变化。源后续变化不加入已确认快照，新增目标记录不被扩大删除。
- A5：仅成功提交批次计入已提交；约束/SQL 失败回滚当前批并停止后续批，先前提交保留；停止在可控边界生效。记录区分已提交、已回滚、未执行与待核实，进程异常和未知提交不自动重试。
- A6：删除保持触发器及外键启用。RESTRICT/NO ACTION 引用冲突可解释并回滚；会导致跨表删除/修改的 CASCADE、SET NULL 和无法证明副作用边界的目标触发器阻止自动执行，预览说明具体对象。精确复合键、排序规则等价键、BIGINT/DECIMAL、NULL、二进制及完整旧值校验不失真。
- A7：上下文变化使旧计划及删除确认失效，执行与结构写入互斥并保护退出；持久记录含完全对齐模式、删除计划数量、实际批次结果及脱敏错误，不保存可重放业务参数。重启不恢复可执行计划，未完成记录标待核实，临时值按既有生命周期清理。
- A8：真实 Qt 数据页完成完全对齐预览、删除确认、执行、失败/停止反馈、记录和原上下文重新比对；成功执行与复核一致分开表达。前端、原生、D3/D4/D5 受影响回归通过，未执行的平台与故障注入如实标记。

# Constraints and invariants

完全对齐仅指扫描快照对应的键集合及选定字段，不代表全字段、跨表或任意未来时刻一致。删除的是范围内整条目标记录，包括未参与比较的列；预览与确认必须明确此点。无条件代表全表，空源不是扫描失败，也不能跳过删除确认。

批次独立提交，不声称任务整体原子性。不隐式纳入扫描后新出现的目标键。依赖或事务副作用无法可靠证明时保守阻止；不扩展 D5 对复杂触发器的支持。

复用既有 Qt/MySQL/Node 与测试体系。实库写入验证仅使用测试自行创建的独立临时 MySQL，不连接现有业务库。

# Decisions

- Comet Native，当前干净 main 创建，单一紧密关联 change；计划、执行与确认共用现有核心链，拆分增加同文件协调成本。
- 延续总体规划：默认补齐，完全对齐须显式选择，删除单独列出并确认；完全扫描、可靠键、共享范围和单向写入是前提。
- 继承 D5 保守副作用边界，新增对删除级联的明确阻止；不以关闭约束实现成功。
- 开发候选需独立只读复核，之后由 Runtime 检查及独立 Verifier 验收。
