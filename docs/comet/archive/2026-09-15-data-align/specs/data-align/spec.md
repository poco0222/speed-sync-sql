# 范围内数据完全对齐

## Purpose

在 D4 完整精确比对和 D5 补齐/合并更新基础上增加显式完全对齐模式。D4 保持只读，D5 两种模式保持不删除；默认仍为补齐。

## 方向、范围与结果

左右固定，支持两种单向方向，每份计划只写一端。完全对齐插入源独有键、更新同键选定差异字段、删除目标范围内独有键。键与未选字段不被 UPDATE，生成列由目标计算。删除移除整条记录，包含未参与比较的列，确认明确此含义。

范围是经映射应用于两端的共享 AND 条件；页面搜索、分类、分页不改变计划范围。无条件明确标全表。只有完整、成功且当前有效的扫描可判定缺失；失败、取消、抽样或无可靠键不能执行。空源完整扫描允许计划删除范围内全部目标记录，仍须完整删除确认。

范围外目标行保持不变。源范围内键命中目标范围外同键时，按目标真实数据库键语义报冲突，不插入替代、不转为更新或删除。扫描后新出现的目标键不加入删除；执行依据源扫描快照，不承诺双端同时刻快照或持续一致。

## 资格和预览

沿用 D5 的 InnoDB、完整兼容主键/非空唯一键、字段/生成列/必填列/默认值、自增、精确值及依赖可见性检查。不能可靠处理的定义给出原因并禁止执行，不使用 REPLACE、TRUNCATE、隐式截断或关闭约束。

计划绑定当前扫描、连接版本、库表、方向、模式、键、字段、筛选及两端结构。后端保存完整值与有界临时计划，前端分页显示。预览含实际写入端、模式、范围、键/字段、读取时间和一致性限制、增改删数、参数化 SQL 及有限样例；删除明细独立可查。

预览不写库。非零删除需要显式确认删除数量、范围及整行删除含义，之后执行摘要确认绑定当前不可复用计划身份；后端拒绝缺少删除确认、过期及重复执行。模式或上下文改变清除确认。零操作显示无变更。

## 冲突、删除与事务

沿用 D5 有界分批及结构复核。删除在同一目标事务内按可靠键 SELECT FOR UPDATE，比较扫描时完整目标旧值和范围字段，再执行参数化 DELETE，要求恰好删除预期一行。键引用正确，BIGINT/DECIMAL、复合键、二进制及微秒值不经 JavaScript 数值转换损失精度。目标值变化、消失、移出范围或结构/权限变化导致本批失败，不扩大匹配范围。

外键、CHECK、触发器保持启用。可见 RESTRICT/NO ACTION 引用由数据库约束阻止不合法删除，错误说明对象或原因并回滚当前批。删除可能触发 CASCADE、SET NULL 等跨表修改时阻止自动执行；依赖不可见、目标触发器无法证明副作用边界时同样阻止并说明。沿用 D5 可证明安全的简单触发器边界，不自动修复其他表或承诺副作用表与源一致。

任何冲突/错误停止后续批次，本批回滚，先前确认提交保留。停止在可控操作/事务边界响应，不强杀冒充回滚。仅明确提交成功计数；提交不明、回滚无法确认或进程异常标待核实，禁止自动重试。结果区分已提交、已回滚、未执行及待核实。

## 生命周期与复核

连接、表、字段、筛选、方向、模式、重新扫描或结构执行使计划过期，迟到回调不能复活旧计划。写入时锁定上下文，与结构执行互斥，退出保护沿用现有逻辑。

记录含实际端点别名/库表、方向、完全对齐模式、时间、计划增改删数量、实际提交与批次状态、脱敏错误；不保存整行敏感值、密码或可重放参数。重启将未完成执行标待核实，不恢复可执行计划。临时计划与值按既有失效、关闭、启动清理策略回收。

执行后可回到相同上下文重新比对。执行成功不等于复核无差异；范围和字段定义保持可见，目标触发器或后续并发变化可能使复核不同。
