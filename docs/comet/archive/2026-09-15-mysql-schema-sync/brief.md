# Outcome

为内部人员规划 MySQL 单表结构比对与双向同步桌面工具。本次 change 仅交付总体范围与目标、功能可行性、总体功能清单、页面布局与交互设计、后续开发阶段建议。用户将在本次 change 完成后新建其他 change，分阶段开发。本次不实施业务代码、不安装业务依赖、不搭建可运行工程。

# Scope

- 已确认：输入两端 MySQL 连接，选择单表，比较结构、字段、触发器及相关结构对象；按差异选择同步方向。
- 已确认：Qt6、React 19.2.7、TypeScript 6.0.3、Ant Design 6.4.5；保留 Ant Design 组件，不大规模自制组件。
- 已确认：当前为空项目，本次初始化限工作流与设计文档；工程初始化留给后续开发 change。高级产品经理视角，重视操作友好、便利、审美和使用意愿。
- 已确认：Windows、macOS 都需要正式使用；MySQL 以 8.0 及以上为目标，具体版本与特性兼容矩阵在后续技术验证中限定。
- 已确认：总体功能包含表数据同步；本次梳理模式和边界，具体实现留给后续 change。
- 总体结构范围建议：字段、索引、主键、外键、CHECK、表属性、触发器；跨版本与特殊对象的可执行范围需在设计中明确。
- 拟议流程：连接两端 → 选表 → 看差异 → 选择方向与条目 → SQL 预览 → 执行 → 重新比对。
- 已确认设计见 docs/design/README.md，包含总体功能、可行性、页面交互与后续路线；PRODUCT.md 单独保存用户已确认事实。

# Non-goals

- 已确认：其他数据库类型、过度安全体系。
- 已确认排除：用户角色管理、审批中心、定时任务、持续复制、整库迁移、自动识别重命名、跨库自动依赖改写。
- 本次不实施数据库连接、比对引擎、SQL 执行、表数据同步、桌面打包或可运行界面。
- 后续开发阶段仅作为路线建议，不在本次 change 下创建或启动开发子任务。

# Acceptance examples

- A1：可行性结论区分已核实的技术事实、产品建议、待验证边界；不把依赖声明当作运行验证。
- A2：设计明确覆盖连接、单表选择、对象差异、方向选择、SQL 预览、执行结果及重新比对。
- A3：交互设计覆盖无连接、加载、空结果、单端缺表、无差异、读取失败、执行部分失败状态。
- A4：页面方案以 Ant Design 组件为主，差异文本可扫读，写入端始终明确，不使用营销页装饰替代工具功能。
- A5：总体功能清单包含表数据同步的建议模式、适用条件和边界，并与结构同步区分。
- A6：交付明确列出后续独立开发 change 的建议范围、依赖和阶段目标；本次没有业务实现或依赖安装。

# Constraints and invariants

- 内部使用，防护聚焦误操作与执行正确性，不扩展为安全治理系统。
- 相互替换的产品语义拟定为每次计划明确一个写入方向；不将双向同步解释为自动冲突合并。
- MySQL DDL 存在隐式提交；不承诺多语句整体回滚。结构快照不等于数据备份。
- 目标系统为 Windows 与 macOS；具体 Qt 版本和工具链在后续工程 change 中核查，优先复用 /Users/PopoY/Documents/DevTools。
- 当前目录不在 Git 仓库中；未初始化 Git，也不建立 CodeGraph 索引。

# Decisions

- 使用 Comet Native，在当前目录梳理一个紧密关联的产品 change。
- 用户明确本次为完整产品规划与设计 change；分阶段开发将在新 change 中独立进行，不将规划阶段误作首版开发授权。
- 用户允许忽略首次工作流解析输出中的初始化前缀，采用尾部有效 JSON 的 native 路由。
- 界面设计以 Impeccable 的 Operate 场景为基础；design-taste-frontend 不适用于密集工具界面，仅取适用的视觉克制原则，Ant Design 优先。
- npm Registry 已核实三个指定前端版本存在；antd 6.4.5 的 React 与 react-dom peerDependencies 均为 >=18.0.0。尚未安装和构建。
- 架构建议：Qt WebEngine 承载 React，通过 WebChannel 异步桥接到 C++ 数据库服务；最终 Qt 驱动与打包待验证。
- 总体候选提出 23 项功能、7 个未来独立开发阶段；每次同步计划只写入一端，数据同步区分补齐、合并更新和完全对齐。
- 本次界面交付为布局线框、交互/状态及视觉规范候选；不生成产品代码或宣称已有高保真实现截图。
- 用户在布局选择页明确选择 B「对照工作台」（model-pick）：顶部连接、左侧表导航、主区左右对齐、底部按需展开计划；不提供 A/B 布局切换功能。
- 用户已明确确认完整 Shape：总体方案、布局 B、功能模式、A1-A6 文档验收和仅规划不开发的边界。
