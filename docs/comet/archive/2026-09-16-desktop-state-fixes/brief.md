# Outcome

修复 D1–D7 复核报告中的 R1/R2/R3，保持现有数据与结构写入规则。

# Scope

- R1：独立传递数据写入状态；执行期间锁定连接、库表、设置及历史恢复等上下文入口，页脚显示数据写入；只读扫描仍允许切换连接。
- R2：主题、密度与默认连接超时保存不删除当前扫描/计划；超时只作用于后续任务连接，不改变已启动任务。写入期间设置仍禁用。
- R3：同一应用数据目录限定一个 Foundation 持有者；锁在配置读取、临时目录清理和记录恢复前取得。第二实例明确报占用，不能读写共享状态或恢复记录；正常退出释放锁，异常退出后的死锁文件通过 QLockFile 既有进程存活检测处理。不同目录互不影响。
- 沿用当前 main 与目录；已有未提交复核报告属于同一修复范围。

# Non-goals

不启动远程 CI、不补最低系统/干净机器平台验收、不改变 SQL/事务语义、不升级依赖、不合并推送。

# Acceptance examples

- A1：真实 Qt 数据写入期间，连接选择、编辑、库表输入、设置与历史恢复入口禁用，页脚标数据写入；停止按钮仍可用，结束后恢复控件；原生上下文锁回归通过。
- A2：只读扫描期间仍可切换连接或取消，旧结果不会回填；结构同步与数据写入原有互斥保持有效。
- A3：现有前端构建/测试、原生构建/CTest、D4 与 D5/D6 相关隔离 MySQL/真实 Qt 回归通过；证据与未运行的平台边界如实记录。

A3/A4 原验收项改为后续验证限制，保留在本 change 的 Scope/Non-goals 与验证记录中，不作为本次归档门槛。

# Constraints and invariants

仅使用自建临时 MySQL 与测试配置目录；不操作业务库或用户凭据。保留扫描精度、删除确认、批次事务、停止边界及 unknown 语义。测试生成物位于忽略目录。

# Decisions

- 用户在阅读三个问题与修复建议后回复“可以”，授权修复这三项并验证；本次将原已审阅修复范围具体化，不扩大交付。
- 采用单个 Native change；状态传递和生命周期改动紧密关联，根代理实施，候选复核及最终 Verifier 独立只读。
- R3 采用报告推荐的同目录单实例方案，无跨实例同步或自动聚焦窗口功能。
