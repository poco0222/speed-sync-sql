# VS Code 原生调试

## 目标与平台

当前 macOS arm64 开发机从项目根目录按 F5，构建并启动 Speed Sync SQL 的 Debug 桌面应用。调试器复用已安装的 Microsoft C/C++ 扩展与 LLDB。

## 构建与启动

默认启动配置引用项目级预启动任务。任务依次准备并构建前端资源、配置 CMake Debug 构建、通过 CMake --clean-first 清理后重新编译项目全部原生目标与资源、重新链接应用并复制 QMYSQL 插件。无论源码或资源哈希是否变化，每次 F5 都执行此前端构建和原生全量重建；直接运行共享 macOS 构建脚本也遵循该行为。清理只作用于 CMake 管理的构建产物，不重编第三方 Qt/MySQL 库、不删除用户数据。任务失败时不可自动启动旧程序。应用路径基于工作区，Qt/CMake/Ninja 使用现有 DevTools 和构建脚本的路径约定及覆盖机制。

## 调试行为

支持原生主进程 C++ 源码断点、继续和停止。默认调试沿用应用数据行为，验证使用独立临时数据目录且不连接现有数据库。不承诺 React 浏览器断点或数据库工作子进程自动附加。

## 说明与验证

README 说明根目录打开方式、F5 操作、必要扩展与工具，以及平台和调试范围。连续两次在源码不变时运行任务，验证前端均重新构建、原生均清理并编译和链接，核对测试通过；既有调试启动与断点语义保持。无法实测的 VS Code 交互环节应明确记录，不称为通过。

## 非目标

本次不新增 Windows 调试、发行打包、全局工具安装或业务功能变更。
