# 页面布局与交互设计

状态：用户已选择 B「对照工作台」并确认整体方案，不是已实现界面。所有示例表名、差异与数量均为示例数据。整体阅读方式：面向内部数据库操作人员的桌面工作台，视觉克制、信息清晰，以 Ant Design 为唯一控件系统。

## 1. 设计判断

本工具最值得突出的内容是“这个对象哪里不同”和“选中后会怎样变化”。设计采用 Operate(操作)模式，布局变化度 3/10、动效强度 2/10、信息密度 7/10。使用系统字体、规则对齐、清楚的差异状态和短路径交互；不做展示型首页。

### 布局决定

| 方案 | 组织方式 | 优势 | 代价 |
| --- | --- | --- | --- |
| A 变更清单工作台 | 主区按新增/修改/删除组织，每项展开左右值；右侧常驻计划摘要 | 执行动作集中，易检查“将修改什么” | 查看整体字段顺序和两端原貌需要展开，连续阅读结构略慢 |
| B 对照工作台（用户已选） | 左侧表导航，主区始终左右对齐，底部按需打开计划预览 | 结构与数据都能沿用，选表到比对最直接，长字段也可比较 | 形态较熟悉，品质取决于排版、细节与空白控制 |

用户已在布局选择页选择 B（model-pick）。后文统一采用 B；A 仅保留为方案比较记录，不作为产品中的布局切换功能。保持 Ant Design，不发展第二套组件语言。

方向探索同时检查了依赖网络、折叠通道、消费型卡片、固定标尺图鉴、叠层数值、终端日志等形式。网络不适合直接承载大量字段；折叠与卡片隐藏对照关系；叠层文字和终端式控制削弱标准控件。保留其中有用的约束：依赖可追溯、展开不丢上下文、按钮文案直接、左右严格对齐、过期状态明显、日志可定位。它们作为操作纪律，不引入造型、纹理、发光或特殊导航。

## 2. 页面与层级

| 页面/区域 | 用途 | 进入方式 |
| --- | --- | --- |
| 比对工作台 | 选连接、选表、结构/数据比对、选变更 | 默认入口 |
| 连接管理 | 管理常用连接 | 一级导航；选连接时也可就地新建 |
| 执行记录 | 查询已完成、失败、待核实任务 | 一级导航；执行完成后直达当前记录 |
| 设置 | 主题、密度、超时与布局恢复 | 一级导航中的轻量入口 |
| 连接编辑抽屉 | 新建/修改连接、测试 | 工作台和连接管理共用 |
| 对象详情侧栏 | 触发器、长字段、依赖、原始定义 | 点击对象名或详情按钮 |
| 同步预览底部面板 | 查看摘要、SQL/数据操作、发起执行 | “预览同步” |
| 执行确认弹窗 | 明确写入端与破坏性变更 | 预览面板中的“执行到右侧/左侧” |

避免把结构、数据、SQL 和结果拆成互不相干的多页向导。首页不提供无意义统计大卡片，不设置账号登录或角色菜单。

## 3. 工作台布局

以下为区域线框，不是像素级效果图。1440×900 是设计参考尺寸，不是强制窗口尺寸。

```text
┌────────────────────────────────────────────────────────────────────────────┐
│ Speed Sync SQL    比对工作台   连接管理   执行记录                 设置      │
├────────────────────────────────────────────────────────────────────────────┤
│ 左侧 [测试连接 / app_test ▾]    [左 → 右 ▾]    右侧 [预发 / app_stage ▾]     │
│ 已连接 · MySQL 8.x                              已连接 · MySQL 8.x          │
├────────────────┬───────────────────────────────────────────────────────────┤
│ 表 [搜索表名]   │ orders → orders          结构 | 数据       [刷新比对]      │
│ [全部 ▾]       ├───────────────────────────────────────────────────────────┤
│                │ 字段 | 索引 | 约束 | 触发器 | 表属性 | 原始定义            │
│ orders  不同   │ [搜索对象]  [✓只看差异]                                   │
│ items   相同   ├───┬───────────┬────────────────┬────────────────┬─────────┤
│ config  未比对 │ 选│ 对象      │ 左侧           │ 右侧（写入端） │ 差异    │
│ logs    仅左   │ □ │ status    │ varchar(32)    │ varchar(16)    │ 不同    │
│                │ □ │ remark    │ varchar(255)   │ 不存在         │ 仅左    │
│                │   │           │                │                │         │
│                ├───────────────────────────────────────────────────────────┤
│                │ 已选 2 项     左 → 右              [清空] [预览同步]      │
├────────────────┴───────────────────────────────────────────────────────────┤
│ 读取完成                                               当前无执行任务     │
└────────────────────────────────────────────────────────────────────────────┘
```

参考尺寸：应用导航约 48px，连接区约 76px，表导航默认 240px（可缩至 200px），主区占剩余宽度。间距以 4/8px 刻度组织；表格常规行高约 40px，紧凑约 32px。布局以内容容纳为准，不让辅助区挤压对照列。

表导航与主区用 Splitter；两端值放在同一个 Table 的分组列中，天然保持行对齐。复杂 DDL 详情才用真正的双栏文本差分；不维护两张容易失步的独立表格。

表状态只在已比对后显示“不同/相同”。读取表清单不默认扫描整个数据库；尚未比较明确写“未比对”，避免制造已全库检查的假象。

### 3.1 连接与方向

- 左右位置稳定，连接别名与数据库名始终可见；完整地址放在展开详情，写入端额外有文字标识。
- 切换方向使用带文字的 Segmented 或 Select，不用一个没有含义的双箭头图标。
- 切换方向重新生成操作语义和计划；原勾选清空并就地提示，避免新增变删除后仍被默认选中。
- 更换数据库/表配对后清空旧计划，保留个人布局。已有选择时只提示会失效，不形成多重确认链。
- 执行期间锁定当前任务连接、表、方向和计划；其他记录可查看，不能悄悄改变正在执行的上下文。

### 3.2 差异表达

“不同”与“修改”不是同一概念：不同是客观比较结果，修改是按当前方向生成的动作。左/右列固定，选择方向后在摘要显示将新增、修改、删除的对象。

差异只突出变化字段和值，不将整屏行都填满高饱和色。相同值保持正常可读但弱化；未读取显示占位说明。颜色同时配文字/图标，不能只凭红绿判断。

示例：`status` 在左侧是 `varchar(32)`，右侧是 `varchar(16)`。左 → 右计划显示“扩大 status 长度：16 → 32”；反向显示“缩短 status 长度：32 → 16，检查已有数据”。

### 3.3 勾选与依赖

初次比对不默认全选。表头选择明确作用于当前过滤集合，摘要同时显示“已选总数/当前可见数”；切换对象标签保留已选项，底部统一查看全部选择。

选择需要依赖操作的对象时，详情列出关联项及原因，由用户纳入同一计划。未经确认不增加对其他表的修改。不可执行项仍可查看定义，但复选框禁用并附原因。

### 3.4 SQL 预览

点击“预览同步”打开主区下方可调整高度的面板，原差异区仍可见。窄窗口改为主区内全幅预览，有清楚的“返回差异”，不再叠第三个侧栏。

```text
┌────────────────────────────────────────────────────────────────────────────┐
│ 同步到 app_stage.orders       新增 1 / 修改 1 / 删除 0       [收起]          │
├────────────────────────────────────────────────────────────────────────────┤
│ 变更摘要 | SQL                                      [复制] [导出 SQL]     │
│ 1. 扩大 status 长度：16 → 32                                              │
│ 2. 添加 remark                                                           │
│ 关联操作、无法执行原因和版本提示在相关步骤下显示                            │
├────────────────────────────────────────────────────────────────────────────┤
│ 预览未执行。目标结构变化后需刷新计划。          [返回修改] [执行到右侧]     │
└────────────────────────────────────────────────────────────────────────────┘
```

确认弹窗只出现一次，显示连接别名、数据库、表、方向、操作数量和破坏性条目。无须每条 SQL 都弹窗。确认后按钮进入执行状态并防重复提交。

## 4. 数据比对页面

保留上方连接与左侧表导航，主区切换为数据。将匹配键、范围和字段置于可折叠的“比对设置”，不铺满两屏表单。

```text
┌────────────────────────────────────────────────────────────────────────────┐
│ orders          结构 | 数据                                 [开始比对]    │
│ 匹配键 [id ▾]   范围 [全部记录 ▾]   字段 [全部兼容字段 ▾]                 │
├────────────────────────────────────────────────────────────────────────────┤
│ 不同 | 仅左 | 仅右 | 相同      [按键查找]          数据读取时间：本次任务   │
├──────────┬─────────────────────────────────────────────────────────────────┤
│ 记录键   │ 变更字段摘要                                                    │
│ 1042     │ status: 待处理 → 已确认；remark: NULL → 紧急                    │
│ 1087     │ 仅左，右侧缺失                                                  │
├──────────┴─────────────────────────────────────────────────────────────────┤
│ 选中记录详情：字段        左侧值                  右侧值                  │
│                status     待处理                  已确认                  │
│                remark     NULL                    紧急                    │
├────────────────────────────────────────────────────────────────────────────┤
│ 模式 [补齐缺失记录 ▾]     范围 [全部符合条件的差异 ▾]      [预览同步]      │
└────────────────────────────────────────────────────────────────────────────┘
```

示例值仅展示两端内容，动作摘要按当前方向重新计算。默认显示变化字段，必要时切换全部字段。不会把一张几十列的数据表复制两份横向挤在窗口里。

数据页默认不读取整表；用户先确认范围再开始扫描。扫描未完成时显示已扫描数量，完整同步与删除按钮禁用。抽样如未来加入，必须明确标“样例”，不产出完整对齐计划。

数据预览突出模式、匹配键、筛选范围和新增/更新/删除数。“完全对齐”提示范围外数据保留，并列出范围外同键冲突。长字段详情按需加载，NULL 使用独立标记；复制得到原值，不是显示缩略文本。

## 5. 连接管理

连接列表显示名称、主机、端口、上次测试结果；历史测试不冒充实时在线。选中连接可“用作左侧”“用作右侧”，减少在工作台再次查找。

编辑抽屉分基本信息与可折叠高级选项。基本字段：名称、主机、端口（默认 3306）、用户名、密码、可选默认数据库；高级为 TLS/超时等必要连接参数。标签在输入框上方，密码默认隐藏；“记住密码”默认关闭。

“测试连接”和“保存”分开：保存草稿不要求网络可达；测试失败不清空输入。编辑主机/账号等参数后，旧测试结果标记失效。删除连接配置不影响数据库本身，提示文案明确这一点。

## 6. 执行过程与记录

运行中的预览面板转为步骤列表，包含开始时间、实际提交状态和停止按钮。任务总量未知时不做虚假百分比。停止请求显示“正在等待当前操作结束”，退出程序时提示正在运行的任务。

记录列表用紧凑表格，按状态/时间/连接过滤。详情显示摘要、步骤结果和错误原文，可复制诊断信息；不默认显示或持久化整表敏感内容。点击“重新比对”返回相同连接/表组合并重新读取，不能原样重放旧计划。

结构快照标注“原始结构定义”，禁止命名为“完整备份”或提供未经支持的“一键回滚”。数据任务只按真实已提交批次显示成功。

## 7. 状态与恢复

| 状态 | 展示 | 可用动作 |
| --- | --- | --- |
| 未配置连接 | 两端选择区与简短引导，保留工作台轮廓 | 添加连接 |
| 一端未连接/失败 | 错误固定在该端，不覆盖另一端 | 修改、重试 |
| 读取中 | 表格骨架或保留旧结果并标“更新中”，禁用旧计划执行 | 取消读取 |
| 单端缺表 | 空的一端标“表不存在”，不伪造空表结构 | 创建目标表计划或换配对 |
| 相同 | 简短结果说明与“显示全部”，保留上下文 | 切换对象、刷新 |
| 搜索无匹配 | “没有符合当前搜索条件的对象”，保留连接、表与筛选；不表述为两端相同 | 清除搜索、调整筛选 |
| 数据范围内无记录 | 区分两端均无记录与仅一端无记录；只在完整读取后给出结论，保留范围条件 | 修改范围、重新比对 |
| 未支持/权限不足 | 明确原因，不能写成“相同” | 查看定义、重新读取 |
| 无可靠数据键 | 数据页提示原因，写入操作禁用 | 选择可验证唯一键、仅浏览 |
| 计划过期 | 就地横幅，保留参考内容，执行禁用 | 重新比对 |
| 执行中 | 当前步骤、已完成步骤、耗时；上下文锁定 | 请求停止、查看日志 |
| 部分失败 | 成功、失败、未执行分开列出 | 复制错误、重新比对 |
| 提交结果未知 | “结果待核实”，不自动重试 | 连接恢复后核对 |
| 复核仍不同 | 指出剩余差异，不以执行成功等同完全一致 | 返回差异 |

## 8. 视觉规范

### 配色与表面

采用偏冷的中性灰基底和克制的蓝色主操作。候选浅色基底 `#F5F7FA`，主内容白色，正文 `#1F2329`，主操作蓝沿 Ant Design 主色体系。状态红/橙/绿仅作语义使用，不与操作蓝争主次。暗色通过 Ant Design darkAlgorithm 映射，同一窗口统一主题。

上述为设计意图，最终对比度需在后续页面实现中验证；不声称已做像素或 WCAG 实测。Ant Design 的常规白色内容面保留，不为套用营销页规则强行改掉系统色。

### 字体与密度

中文与操作文字用系统无衬线字体，参考正文 14px，辅助文字 12px，区域标题 16px。表名、字段名、SQL 与关键数值采用系统等宽字体；不全屏等宽。长名称可复制并展开，不能靠无限缩小字号容纳。

主内容区用分隔线与间距分组，不在表格外套多层卡片。控件圆角沿 Ant Design，参考 6px；不做胶囊按钮与异形面板。仅浮层保留系统阴影。

### 动作与反馈

当前阶段只突出一个主动作：开始比对、预览同步、执行到右侧/左侧，随阶段变化。复制、导出、刷新作为次要动作。按钮配文案，不能只靠图标表达写入。

动效仅用于抽屉和状态过渡，约 150-200ms；无循环装饰、滚动编舞和页面入场等待。尊重系统减少动效设置。

### Ant Design 对应

| 需求 | 组件方向 | 定制上限 |
| --- | --- | --- |
| 主框架/导航 | Layout、Menu | 少量主题与间距 |
| 双端连接 | Select、Space、Tag、Tooltip | 自定义组合，不重写控件 |
| 区域伸缩 | Splitter | 设置默认宽度、最小宽度与记忆 |
| 对象与数据差异 | Table、Tabs、Checkbox、Input.Search | 行/单元格状态渲染 |
| 连接编辑 | Drawer、Form、Input.Password、Collapse | 字段组织与校验提示 |
| 方向/模式 | Segmented、Select | 固定文字与方向语义 |
| 执行与错误 | Alert、Progress、Table、Result | 真实任务状态，不做装饰性仪表盘 |
| 确认 | Modal | 单次摘要确认与破坏性条目 |
| 主题 | ConfigProvider | token、compactAlgorithm/darkAlgorithm 按需组合 |
| 图标 | @ant-design/icons | 保持同一家族，不手绘图标 |
| 原始 SQL 差分 | 后续选择成熟差分编辑器 | 仅编辑器是专用组件，不带入另一套 UI 系统 |

## 9. 双平台、窗口与键盘

保留平台原生窗口按钮和系统菜单约定。Windows 用 Ctrl、macOS 用 Cmd 表示复制与查找；破坏性执行不绑定无确认快捷键。Tab 顺序符合视觉顺序，焦点样式沿用 Ant Design。窗口缩放用逻辑尺寸，后续验证高 DPI 与中文字体。

推荐完整工作区宽度约 1280px 及以上；更窄时先收起表导航，再将预览改为主区内全幅。表格只在自身区域水平滚动，关键操作区固定可达。高缩放/更小窗口提供按属性逐项对照布局，不能以隐藏写入端或主按钮解决空间不足。

设计检查目标为 1440×900、1280×800、约 1024px 宽及高缩放。它们是后续验收场景，不是本轮已截图验证。移动设备不纳入目标，不为了手机布局牺牲桌面对照效率。

## 10. 后续实施验收提示

执行前不出现方向歧义；刷新/换表不会沿用旧计划；长表名与错误不会挤走按钮；只看差异和跨标签选区行为明确；浅/深主题下状态有文字且可辨；执行失败可定位到具体步骤；数据展示截断不影响真实比较。总体功能规则以 [overview.md](overview.md) 为准。
