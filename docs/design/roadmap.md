# 后续开发 change 建议

本文只划分未来工作，不创建或启动任何开发 change。用户在本次规划与设计确认完成后，按需要另开 change。每次只展开当期实现细节，沿用总体产品规则；新增需求再明确扩展。

## 1. 分阶段路线

| 阶段 | 建议 change 名称 | 阶段目标 | 交付与验收边界 | 依赖 |
| --- | --- | --- | --- | --- |
| D1 | desktop-foundation | 让双平台基础成立 | 初始化工程，Qt/React 桥接、Ant Design 框架、连接表单与测试；Windows/macOS 均有启动和 QMYSQL 加载证据；确定 OS/架构/Qt 版本 | 本次设计确认 |
| D2 | schema-compare | 先成为好用的只读比对工具 | 库表选择、结构化元数据、对象分类、差异/原始定义查看；未读取/失败/不支持不误报一致；可导出差异摘要 | D1 |
| D3 | schema-sync | 完成常规结构同步闭环 | 方向与选区、依赖、SQL 预览、结构快照、执行与复核、记录；支持范围在该 change 明确，特殊对象可仅展示 | D2 |
| D4 | data-compare | 看清单表记录差异 | 可靠键、兼容字段与筛选、分页/分批读取、精确值、记录详情；不写入数据 | D2 |
| D5 | data-merge | 提供受控的数据写入 | 补齐与合并更新、操作预览、冲突检查、分批结果、停止和复核；不删除目标独有记录 | D3、D4 |
| D6 | data-align | 完成范围内数据对齐 | 在完整扫描与明确键/范围基础上增加删除；范围外同键冲突、目标触发器/外键影响、部分失败可解释 | D5 |
| D7 | desktop-release | 双平台日常可用 | 干净机器安装、字体/DPI、主题/密度、代表性数据规模、资源/驱动打包与发行说明 | D3；发布数据能力时还需对应 D5/D6 |

D4 不要求 D3 先完成算法，但实际由用户顺序开 change 即可；不为理论并行主动创建子任务。D7 的双平台验证从 D1 开始累积，每阶段做相关平台检查，不能把 macOS 或 Windows 留到最后才第一次启动。

## 2. 每阶段结束应该能看到什么

- D1：可打开的真实桌面窗口、统一 Ant Design 视觉、两端连接可测；不展示假成功的比对结果。
- D2：用实际表结构看到相同、不同、单端缺失与不支持状态。此时已经可用于人工核对。
- D3：能预览并执行受支持的结构变更，失败后知道哪些已发生。
- D4：能判断哪些记录缺失、哪些字段不同，并明确扫描是否完整。
- D5：能补配置与更新记录，保留目标独有记录。
- D6：能在显式范围内做包含删除的对齐，不误伤范围外记录。
- D7：安装包在目标系统可启动和连接，界面在实际窗口/缩放下可用；性能报告只写实测样本。

## 3. 后续 change 的固定输入

每个开发 change 引用 [PRODUCT.md](../../PRODUCT.md)、[总体功能](overview.md)、[页面设计](interaction-design.md) 与对应功能 ID，只细化本阶段需要的接口、数据模型、SQL 规则和测试。设计变更必须说明改变的用户行为；不把未实现的后续按钮做成可以点击的假功能。

阶段性产品可隐藏尚未实现的数据模式，或在明确的规划说明中呈现；界面不铺满“敬请期待”。跨阶段保留同一连接、表配对、方向和结果语义，避免反复换交互模型。

## 4. 不在本轮承诺的事项

工期/人日、所有 MySQL 未来版本、所有特殊引擎/分区、百万行耗时、自动全局回滚、无锁 ALTER、特定平台安装包签名流程。后续按当期样本和运行证据确定，规划完成不等于这些项目已验证。

## 5. 当前 change 的独立完成条件

只验收规划与设计产物：目标范围完整、技术边界有依据、页面和状态可复核、组件方案符合 Ant Design、开发阶段可独立开启。完成本次 change 不启动 D1，不安装任何业务依赖，不以实现功能作为本次完成条件。
